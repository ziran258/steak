# 架构决策记录

## ADR-001：使用 Next.js 单体应用

决定：第一版使用 Next.js App Router，不拆独立后端。

原因：

- 展示型 Wiki 适合 SSR/SSG 和 SEO。
- 单体复杂度低。
- 后续可自然扩展 API、后台和认证。

## ADR-002：使用腾讯云服务器 + Dokploy

决定：部署优先使用腾讯云 Ubuntu + Dokploy。

原因：

- 项目目标包含练习云服务器和自托管部署。
- Dokploy 能降低直接维护 Docker/Traefik 的复杂度。
- 后续可在同一服务器管理多个服务。

## ADR-003：第一版不接 Better Auth

决定：第一版不做登录和后台。

原因：

- 当前只展示信息。
- 过早接入认证会增加复杂度。
- 等需要后台、投稿、收藏或评论时再接入。

## ADR-004：第一版图片放 public 目录

决定：第一版使用占位图，不接 Cloudflare R2。

原因：

- 每条内容暂定 1 张图，规模较小。
- 暂无后台上传。
- 数据字段使用 URL 形式，后续可平滑迁移到 R2。

## ADR-005：使用结构化实体 + 双语翻译表

决定：不采用“万物皆文章”的模型。

原因：

- 项目核心是知识关系，不是博客。
- 部位、产地、等级、术语、厂号需要结构化展示。
- 双语翻译表方便后续扩展更多语言。
